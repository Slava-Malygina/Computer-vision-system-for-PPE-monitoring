# Архитектура веб-панели журнала нарушений

## Общее назначение

Веб-панель журнала нарушений представляет собой вторичный пользовательский интерфейс системы мониторинга СИЗ, предназначенный исключительно для аналитической работы сотрудников руководства и инженеров по технике безопасности. В отличие от десктопного приложения, ориентированного на оперативный мониторинг, веб-панель фокусируется на анализе исторических данных, визуализации статистики и формировании отчётности.

## Технологический стек

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| Веб-фреймворк | Flask 2.x | Минималистичный WSGI-фреймворк, легко интегрируется с существующей Python-базой проекта, не требует сложной конфигурации. |
| Шаблонизация | Jinja2 | Встроен в Flask, поддерживает наследование шаблонов, условную логику и циклы. |
| База данных | SQLite 3 | Используется общей системой; обеспечивает целостность данных и совместимость с десктопным приложением. |
| Экспорт отчётов | pandas + openpyxl (Excel), ReportLab (PDF) | Уже применяются в проекте. |
| Визуализация | Chart.js | Лёгкая JavaScript-библиотека для построения диаграмм в браузере. |

## Описание экранов

### 4.1. Страница «Журнал нарушений» (/journal)

**Назначение:** просмотр и фильтрация записей о нарушениях.

**Элементы интерфейса:**

- **Панель фильтров:**
  - Множественный выбор камер (чекбоксы)
  - Множественный выбор типов нарушений («Без каски», «Без жилета», «Без перчаток»)
  - Диапазон дат («с» / «по»)
  - Диапазон времени («с» / «по»)
  - Ползунок вероятности (0% – 100%)

- **Таблица нарушений:**
  - Колонки: Дата, Время, ID нарушителя, Тип нарушения, Вероятность, ID камеры, Путь к скриншоту
  - Поддержка сортировки по любой колонке (кликом по заголовку)

- **Навигация:** пагинация (10/25/50/100 записей на странице)

**Поведение:**
- Все фильтры применяются серверной логикой (SQL WHERE)
- При первом заходе отображаются все записи за последние 7 дней

---

### 4.2. Страница «Аналитика и отчёты» (/analytics)

**Назначение:** визуализация статистики и экспорт отчётов.

**Элементы интерфейса:**

- **Диаграмма 1:** Распределение нарушений по типам
  - Круговая диаграмма: % «Без каски» / «Без жилета» / «Без перчаток» за выбранный период

- **Диаграмма 2:** Динамика нарушений по дням
  - Линейный график: количество нарушений в день за последнюю неделю/месяц

- **Панель экспорта:**
  - Радиокнопки: «Полный отчёт» / «Отфильтрованный отчёт»
  - Выбор формата: CSV, XLSX, PDF
  - Кнопка «Скачать отчёт»

**Поведение:**
- Диаграммы обновляются при изменении временного диапазона
- Экспорт учитывает текущие фильтры (если выбран «Отфильтрованный отчёт»)


## 5. Маршруты (endpoints)

| HTTP-метод | URL | Назначение |
|------------|-----|-------------|
| GET | /journal | Отображение журнала с фильтрацией через query-параметры |
| GET | /analytics | Отображение аналитических диаграмм и панели экспорта |
| GET | /api/violations | JSON API для получения данных (используется Chart.js) |
| GET | /export/excel | Генерация и скачивание отчёта в формате XLSX |
| GET | /export/pdf | Генерация и скачивание отчёта в формате PDF |

## 6. Взаимодействие с базой данных

Веб-панель не содержит собственной логики работы с БД. Вся работа делегирована общему модулю `modules.database.DatabaseManager`, который:

- обеспечивает потокобезопасный доступ к violations.db
- предоставляет методы:
  - `get_violations()` — получение записей с фильтрацией
  - `get_violations_count()` — получение количества записей
  - `get_statistics()` — получение статистики для аналитики
- гарантирует целостность данных при одновременной работе десктопного и веб-интерфейсов

---
### Взаимодействие компонентов:

**Десктопное приложение (PyQt6)** — основная система детекции нарушений. Записывает данные о нарушениях в общую базу данных.

**Веб-панель (Flask)** — предоставляет веб-интерфейс для просмотра журнала нарушений, аналитики и экспорта отчётов. Читает данные из той же базы данных.

**Общая SQLite-база (violations.db)** — единое хранилище данных, обеспечивающее:
  - Совместимость между десктопным и веб-интерфейсом
  - Потокобезопасный доступ через DatabaseManager
  - Целостность данных при одновременной работе
  
## 7. Безопасность

**Сетевой уровень:**
- Доступ разрешён только из локальной подсети предприятия (192.168.0.0/16, 10.0.0.0/8)
- Порт 5000 закрыт от интернета на уровне корпоративного фаервола

**Аутентификация:**
- Реализована HTTP Basic Authentication (логин/пароль), активируемая через конфигурационный флаг

**Защита данных:**
- Персональные данные не передаются
- Скриншоты автоматически удаляются через 30 дней

### 1. Создание структуры проекта

- Создать папку `web/` в корне репозитория
- Внутри создать:
  - `app.py` — точка входа Flask-приложения
  - `requirements.txt` — зависимости (Flask, pandas, openpyxl, reportlab)
  - `templates/` — папка для HTML-шаблонов
  - `static/` — папка для CSS, JS, иконок
- Убедиться, что из `web/app.py` можно импортировать модули из корня (например, `from modules.database import DatabaseManager`)

*Ссылка на архитектуру: см. раздел «Структура проекта» в docs/web_panel_architecture.md*
